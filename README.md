# OnOffMyPC Design

The cross-platform source of truth for OnOffMyPC's visual language and
product-state presentation. It keeps the web, Android, iOS, firmware setup,
and transactional email surfaces recognizably related without forcing them to
share UI implementation code.

## Product character

OnOffMyPC is an operational control surface. It should feel calm, precise, and
trustworthy: quiet green-tinted neutrals, blue interaction affordances, and
status colors reserved for real device meaning. Native controls and navigation
remain native. Decorative effects never compete with device state.

## Repository boundaries

- `tokens/` owns visual primitives and light/dark semantic roles.
- `states/` owns the presentation of backend-defined machine states. It does
  not own backend state transitions.
- `content/` owns approved default English for trust-critical feedback.
- `assets/` owns source brand and interface vectors.
- `docs/` owns visual, component, accessibility, and contribution guidance.
- `dist/` is generated by `pnpm build`; consumers must not edit it.

Start with [the visual language](docs/VISUAL_LANGUAGE.md),
[component guidance](docs/COMPONENTS.md), [accessibility standards](docs/ACCESSIBILITY.md),
and [UX writing rules](docs/UX_WRITING.md).

The API remains authoritative for command, device, billing, and provisioning
contracts. A design release must map every state exhaustively and must never
claim physical PC state from command acknowledgement alone.

## Commands

```bash
corepack pnpm build
corepack pnpm check
corepack pnpm check:consumers
corepack pnpm sync:consumers
corepack pnpm test
```

`check` regenerates in memory and fails when checked-in output is missing or
stale. Generated artifacts include CSS, Compose, SwiftUI, firmware, email, and
a checksum manifest.

`check:consumers` is a workspace integration check. It validates design,
generated-manifest, and consumer versions and paths, verifies canonical
artifact checksums, then compares every vendored file in `consumers.json`
byte-for-byte. `sync:consumers` performs the same preflight and updates only
existing regular files. It refuses missing destinations, path traversal, Git
metadata, and symbolic links, and rolls back earlier writes if an update fails.

Run either consumer command from a workspace containing the sibling product
repositories. Pass `--workspace-root <path>` when they do not share the design
repository's parent directory. Standalone design-repository CI intentionally
tests this behavior with temporary fixtures instead of requiring sibling
checkouts.

Open `examples/index.html` from a local static server for the reference gallery.

## Adoption

During `0.x`, generated outputs are vendored into consumer repositories through
reviewed update pull requests. Package publication can replace vendoring once
the interfaces stabilize. Consumers pin a design version and retain temporary
aliases while existing UI is migrated.

Canonical brand assets follow the same byte-for-byte distribution rule. The
web and web-app favicons are registered consumers of the generated brand mark.
