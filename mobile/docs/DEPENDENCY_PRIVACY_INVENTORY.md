# Mobile Dependency and Privacy Inventory

Status: source inventory, 2026-11-24. This document describes what is present in
`onoffmypc/mobile` at this revision. It is not a legal privacy notice and it is
not a substitute for the production privacy policy.

Scope: Android and iOS clients only. Backend retention, Cloudflare/D1 behavior,
Polar payment handling, and Firebase/Google account-level data processing are
outside this repository; where those matter they are called out as unknown or
as a server-side dependency.

Method: reviewed the committed Gradle build/settings/properties files and version
catalog, Android manifest and resource XML, iOS XcodeGen spec and entitlements,
Kotlin/Swift networking and storage code, Play Store instructions, and the local
release build artifacts that happen to be present in this workspace
(`sdkDependencies.txt` and the merged release manifest). Those artifacts were not
regenerated on this Linux host. No device, emulator, Android SDK, or Xcode
toolchain was available, so runtime behavior is not claimed as verified here.
The repeatable device checks live in [`ON_DEVICE_VALIDATION.md`](ON_DEVICE_VALIDATION.md).

401, and an expired/empty `session` cookie. iOS clears on logout and HTTP 401,

timeout or biometric app lock; anyone who can unlock the device and open the app
can use an existing session.

### Clipboard, screenshots, and logging behavior

Android:

- `copySensitiveText` copies pairing codes and device tokens through
  `ClipData` and, on Android 13+ (API 33), sets
  `ClipDescription.EXTRA_IS_SENSITIVE` so the system suppresses the clipboard
  preview (`ui/components/SensitiveClipboard.kt:11-21`). Android 12 and older
  receive no such marker.
- Credential and pairing dialogs call `SecureDialogContent()`, which adds
  `WindowManager.LayoutParams.FLAG_SECURE` to the dialog/app window while
  composed (`ui/components/SecureDialogContent.kt:15-23`). That blocks
  screenshots/screen recording and the recents thumbnail for that window; the
  flag is cleared when the dialog leaves composition.
- The clipboard is not automatically cleared after a timeout. A copied token or
  pairing code remains available to other apps/IME and to the clipboard history
  until overwritten or cleared by the user.
- Release builds do not add `HttpLoggingInterceptor`; debug builds log only
  `BASIC` request/response lines, not bodies or headers. Avoid sharing debug
  logcat output because URLs can contain device IDs.

iOS:

- Device ID/token copies use `UIPasteboard` with `.localOnly`, preventing
  Universal Clipboard/Handoff propagation to another device
  (`Components/TokenReveal.swift:62-69`). The clipboard is not cleared after a
  timeout.
- There is no iOS `FLAG_SECURE` equivalent. The one-time credential screen can
  be screenshotted, screen-recorded, and captured in the app switcher. This is
  an accepted known gap in source, not a tested pass.
- Password fields use `SecureField` unless the user taps the show/hide eye
  (`Components/PasswordField.swift:24-35`); while shown, the password is a
  normal `TextField`.
- No app-level `print`/`os_log` calls or HTTP body logging were found in the
  reviewed sources.

|---|---|---|---|---|

## Unknowns and follow-up verification

- Exact iOS GoogleSignIn and transitive package versions; generate
  `Package.resolved` on macOS.
- Actual merged manifest and permissions after a fresh release build; the
  checked-in source manifest has only INTERNET and POST_NOTIFICATIONS, while
  FCM/Google Play services add transitive permissions.
- Server-side retention/deletion execution, database backups, and Polar/Firebase
  data-processing terms.
- Whether iOS `URLSession` disk cache actually contains authenticated responses
  and whether it is excluded from backups.
- Whether iOS follows an authenticated redirect and whether the manually set
  `Cookie` header or a redirected `Set-Cookie` can replace the stored session
  (MP-13); this needs a macOS/unit test.
- Whether Android `bmgr`/OEM migration actually ignores the app on each tested
  OS/device; static rules are not a substitute for a restore/transfer test.
- Whether the iOS app needs a privacy manifest for the specific APIs it uses
  (`UserDefaults`, file timestamps, etc.) and what App Store privacy labels
  should declare.
- Future APNs implementation details: entitlement, token storage, notification
  content, and unregister behavior.

## Maintenance

Re-run `node mobile/scripts/check-mobile-hardening.mjs` and
`node mobile/scripts/test-mobile-hardening.mjs` after dependency, manifest,
backup-rule, network-security, Keychain, clipboard, or screenshot changes. The
gate scans all Gradle build/settings/properties files and version catalogs plus,
when present, the resolved release `sdkDependencies.txt` and merged release
manifest. It parses manifest/resource XML rather than matching exact substrings,
and includes a negative Adjust fixture, but it is still not a packaged-APK
check. Regenerate `sdkDependencies.txt` on a host with the Android SDK, and
generate/review `Package.resolved` on macOS. Update this document when a new
SDK, permission, API field, local-storage location, or data recipient is
introduced.
