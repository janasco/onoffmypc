# Security assessment status

The private cross-repository architecture and threat model are maintained in the separate private repository (`onoffmypc-private`), under `app/docs/cross-repository/`. They are not public.

Android has an origin-bound session-cookie jar (HTTPS plus exact API host/port, host-only/Secure/HttpOnly, redirects disabled), TLS-only network configuration, backup exclusions, and sensitive credential clipboard/screenshot controls. iOS stores the session in a device-bound, non-synchronizing Keychain item that contains both the cookie and its canonical issuing API origin; a different origin, 401, or logout clears it, and legacy raw-cookie items are deleted instead of replayed. iOS credential copies are local-only. iOS source also requires HTTPS plus the exact API host/port for cookie capture, rejects empty/invalid cookies, blocks redirects, and disables the URL cache; those controls still need macOS/device validation and remain tracked as MP-13/OMP-19. A static mobile-hardening gate scans all Gradle sources plus optional local release artifacts and rejects unreviewed analytics/ads/attribution/crash SDKs including Adjust; it also enforces the origin-bound iOS Keychain and API call sites. The committed iOS privacy manifest now declares the reviewed collected-data types (all linked to the account, none used for tracking, App Functionality only) in addition to no tracking and the UserDefaults required reason; App Store privacy labels and the archive privacy report still require validation. The source-level privacy inventory is in [`DEPENDENCY_PRIVACY_INVENTORY.md`](DEPENDENCY_PRIVACY_INVENTORY.md); repeatable physical-device and iOS checks are in [`ON_DEVICE_VALIDATION.md`](ON_DEVICE_VALIDATION.md).

Android `:app:testDebugUnitTest`, `:app:lintDebug`, and `:app:assembleRelease` passed on 2026-11-24 with SDK 36. Source-level staged API configuration now exists for Android (`-PAPI_BASE_URL`) and iOS (`Staging`/`API_BASE_URL`), with production defaults unchanged; staging build/device validation is still pending. Physical-device backup/restore, screenshot, and signed-release smoke validation; macOS/device validation of the new iOS cookie/redirect/origin-bound Keychain controls (including the staging/production switch and legacy-item upgrade); the iOS release/push pipeline; App Store privacy-label reconciliation and archive privacy-report validation; and the remaining privacy risks listed in the inventory are still open. No on-device or iOS build/test result, and no App Store acceptance, is claimed by the documentation alone.

Do not copy the private assessment into a public repository or release artifact.
